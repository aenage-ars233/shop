# Risk checklist 0.1.0

Заполняется в шаге 3 задания «Релизный пакет». Для каждого пункта — короткий ответ: галочка с подтверждением или отметка непройденного пункта с планом исправления. Flag-пункты, на которые ответ «да», переносятся в секцию «Внимание» PR-описания.

Дата:
Автор:
Базируется на ветке: `feat/release-package`

## Безопасность

- [ ] В коде нет жёстко заданных ключей, токенов, паролей.
- [ ] API-ключи читаются из переменных окружения (`VITE_API_KEY` в `.env`, не в репозитории).
- [ ] Нет зависимостей с известными уязвимостями (`npm audit`).
- [ ] MCP-серверы имеют минимально необходимые разрешения (approve flow настроен).

## Устойчивость проекта

- [ ] API-клиент обрабатывает таймаут и ошибки сервера, фолбэк на кеш работает.
- [ ] Интерфейс показывает состояния `loading`, `retrying`, `fallback` и `failed`.

## Изменения, требующие внимания

Если ответ «да» — добавьте в PR-описание секцию «Внимание» с объяснением.

- [ ] Добавлена новая зависимость в `package.json` (указать причину).
- [ ] Изменён формат хранения в localStorage (`appliedPromo`, `products_cache`).
- [ ] Появились новые переменные окружения (отражено в `.env.example`?).

## Выводы

Коротко, одним абзацем: готов ли релиз к слиянию, что стало known issue, что перенесено в следующий релиз.
