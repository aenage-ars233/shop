# Запрос на слияние: оформление заказа

## Что сделано

Добавлена страница оформления заказа: форма адреса с валидацией, выбор оплаты, экран подтверждения с номером, очистка корзины после оформления. Реализация прошла полный цикл SDD в критической зоне.

Затронутые файлы:
- `src/features/checkout/OrderForm.jsx` — форма с клиентской валидацией.
- `src/features/checkout/CheckoutPage.jsx` — страница `/checkout`.
- `src/api/checkout.js` — API-клиент оформления.
- `src/features/cart/CartContext.jsx` — добавлена `clearCart()`.
- `tests/e2e/checkout.spec.js` — e2e-сценарий оформления.
- `docs/specs/capstone/` — комплект спецификаций (contract.md, architecture.md, risk-register.md).
- `docs/capstone-review.md` — саморевью итоговой доработки.

## Зачем

Финальная доработка: полный магазин с каталогом, корзиной, промокодом, доставкой, интеграцией с API, MCP и подготовкой релиза. Оформление заказа — естественная следующая функция: без неё магазин не закрывает базовый путь покупателя.

## Как проверить

1. Склонировать ветку `feat/capstone-checkout`.
2. `npm install && npm run quality` — модульные тесты, линтер, сборка.
3. `npm run test:e2e` — e2e-сценарий «корзина → оформление → подтверждение».
4. `npm run dev` — пройти вручную: добавить товар в корзину, применить промокод `SALE15`, оформить заказ, убедиться что корзина пустая после успеха.
5. Проверить валидацию: отправка пустой формы не происходит, ошибки под полями.

## Риски

- **Двойная отправка заказа.** Мера: кнопка отправки блокируется на время запроса.
- **API заказов недоступен.** Мера: повтор до 3 раз + сообщение с кнопкой повторной отправки. План отката — скрыть кнопку «Оформить заказ» через флаг функции.
- **Изменение `CartContext`.** Добавлена `clearCart()`. Все потребители обновлены в этом же PR.
- **Оплата имитируется.** Встроенный обработчик всегда подтверждает заказ — для учебного проекта приемлемо.
